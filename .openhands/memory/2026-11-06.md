## Real defects found by writing tests (all fixed)

1. **`deriveOpportunities` counted pre-existing opportunities as created.**
   `createOpportunity` returned the existing row's id for a duplicate dedupe key,
   so the daily report/activity overstated new work. Now returns `null` on dedupe.
2. **Entity consistency summed ALL history.** `dashboardSummary` used
   `SELECT SUM(matches), COUNT(*) FROM entity_facts` — one historical mismatch
   dragged the figure down forever (26/27 = 96.3% even after the site was fixed).
   Fixed to `WHERE ts = (SELECT MAX(ts) FROM entity_facts)` → now 100%.
   **General lesson: an aggregate over an append-only history table is almost
   always the wrong measurement.** Ask "latest snapshot or all-time?" first.
3. **Removed sections were orphaned.** `persistPages` upserted sections but never
   deleted ones that disappeared from the page, so a deleted section kept a row
   and kept consuming a `geo_scores` row → inflated "sections scored".
   Now `DELETE ... WHERE page_id=? AND ordinal NOT IN (...)` after each crawl.
   (FK `ON DELETE CASCADE` on geo_scores.section_id cleans the scores.)
4. `research.ts` — `ResearchNote` not assignable to `Record<string, unknown>`.
5. `initDb is not a function` in tests → tests use `getDb()` (schema applied
   idempotently on first connection; there is no separate initDb export).

## Login lockout (added, verified at runtime)

`LOGIN_MAX_FAILURES=8` in `LOGIN_WINDOW_MS=15min`, counters persisted in
`schema_meta` (`login_fail:<email>`), cleared on success, audited, HTTP 429 +
`Retry-After`. Verified live: 8×401 then 429; correct password while locked → 429.
Clear a stuck lock: `DELETE FROM schema_meta WHERE key LIKE 'login_fail:%'`.

## Follow-up: hosting question → found 3 broken npm scripts + a secret leak

Asked "where would this work for free?", which forced the real question: **can
the daily job run with no server?** It can — `scripts/run.ts` calls the same
orchestrator the HTTP route uses. Verified headless: 6 agents, report saved,
zero HTTP.

- **3 `package.json` scripts pointed at files that never existed** (`job` ->
  `scripts/job.ts`, also `migrate`, `refresh`): `ERR_MODULE_NOT_FOUND`. Only
  `seed.ts` was real. Fixed by writing the three scripts.
- **`.gitignore` had `data/*.db` but the DB is `data/geo-lab.db`** — the `*`
  covers `.db` yet **misses SQLite's `-wal`/`-shm`/`-journal` sidecars**, which
  can contain committed pages. In WAL mode a `-wal` file can hold the owner's
  **scrypt password hash and live session tokens**, and this repo is **public**.
  Now excluded explicitly. **Never commit the lab DB anywhere; it is a
  credential store, not data.**
- Added 3 tests (34 -> 37) and **negative-tested each**: reintroduced the bug,
  watched the test fail, restored. Test B's first mutation was wrong (`data/*.db`
  is a substring of the sidecar lines, so `str.replace` rewrote all four and the
  guard passed) — mutate precisely, then confirm the test fails.
- 37/37, tsc clean, build ✓, CI green.

### Free hosting answer (all quotes from the providers' own docs)
- **Fits free:** Oracle Cloud Always Free (real VM + block volume, "for the life
  of the account" — but **idle instances may be reclaimed** if 95th-pct CPU and
  network < 20% over 7 days, which a sleeping lab hits); GCP **e2-micro** + 30 GB
  persistent disk in us-west1/us-central1/us-east1.
- **Simplest:** **no server at all** — GitHub Actions standard runners are free
  for public repos, run `npm run job` on cron, commit derived JSON only.
- **Does NOT fit free:** Render free web service ("ephemeral filesystem … local
  SQLite databases … are lost") and its free Postgres ("expire 30 days after
  creation"); Vercel/Cloudflare Workers (no persistent FS). Cloudflare D1 free
  is 500 MB and needs a data-layer rewrite.
- **Not free despite reputation:** Fly.io — "$1 of free credit … lasts for
  7 days"; a continuously running 512MB machine + 10GB volume is ~$5.19/mo.
