# 2026-10-25 — Indexing/noindex review (owner report: "leak/slab/laguna pages are noindex")

## Root cause of the report: intentional design, not a defect
The owner saw `200 + noindex, nofollow` on `/leak-detection.html`,
`/slab-leak-detection.html`, `/laguna-niguel.html`. These are the **58 root-level
duplicate stubs** (commit `2cd5fff`, PR #10, 2026-09-13). Each canonicalizes to its
real page under `services/`, `cities/`, `academy/`, `guides/`, `insurance/`.
The canonical pages are indexable (no robots meta, self-canonical, in sitemap,
live 200, no X-Robots-Tag). `robots.txt` welcomes GPTBot/ClaudeBot/PerplexityBot.
So the topic pages are NOT hidden. Recorded correct-as-is in AGENTS.md.

Numbers (148 HTML files): 89 indexable (sitemap = 89, exact set), 59 noindex
= 58 root stubs + `about/straight-flush-plumbing-orange-county.html` (noindex,follow,
ISSUE-013 WON'T FIX, mirrored in llms-full.txt, linked with follow).

## The one genuine defect found: orphaned guides hub
`seo_audit.py` reports `orphan pages (0 internal inbound links)`. The only
indexable orphan was `guides/index.html` — footer "Cost Guides" link points at a
child article (`guides/leak-detection-cost.html`), never the hub. Fixed in PR #83
by retargeting the 3 guide articles' breadcrumb parent at `/guides/`, mirroring
the Academy pattern (`Home > Leak Detection Academy > article`). Visible
breadcrumb + BreadcrumbList JSON-LD change together (AGENTS.md rule).

## Gotcha: `refresh_sitemap.py` churns lastmod on a shallow/odd clone
Running it here rewrote 108 `<lastmod>` lines (2026-10-16 -> 2026-10-23) with no
page added/removed — it derives lastmod from each file's last git commit date.
Reverted it (`git checkout -- sitemap.xml`); the committed sitemap URL set still
matches the indexable set exactly. Open sitemap PRs #74/#80 already touch it.
